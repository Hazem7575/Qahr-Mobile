# QahrMobile packet layouts: Quests. The format is described in Networking\Mobile\MobileLayouts.Loader.cs.
# The other quest packets (2339, 2044, 2378, 2381) are in quest-protocol.txt.

# CMsgTaskStatus 10120 (quests): server = action u16 4, count u16 6, 16 zero bytes, units at 24;
# mobile = action u16 4, count u16 6, u8 8 (last packet flag in requests), units at 12. Unit (12 bytes) on both:
# task id u32 +0, status u16/u32 +4, left time u32 +8.
# Mobile actions (CMsgTaskStatus::Process: "ldrh action; subs #1; tbh" = a jump table indexed by action-1) are the
# SAME numbers as the server's QuestMode: 1 accept (AddAlreadyacceptMissionsystemdata), 2 quit (DelAlreadyaccept...),
# 3 task list (status per unit: 0 accepted, 5 failed, else SetTaskStatus), 4 finished (CNewGuideMgr::ProcesNewGuideTask),
# 8 timed task failed (screen effect), 9 left time; 0 and >9 are ignored.
# From the mobile: 3 + all its task ids (CMissionSystemData::RequestTaskStatus, 80 per packet, u8 8 = 1 on the last)
# = server Review (it answers with the full list when count < 80); 1 accept (CMyShellDlg::OnMyMessage4);
# 4 with status 5 = a timed task ran out (CMissionSystemData::CountDownLimitTask), same as the PC client.
# So no action map: an earlier map (server 1/3/4 -> mobile 2) turned every quest packet into "quit" and the
# mobile showed no quests at all.
[2126 MsgTaskStatus shift 24 12]
