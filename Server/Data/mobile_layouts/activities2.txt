# QahrMobile packet layouts: Activities part 2 (sign-in, benefits, mentor info, slots, roulette, horse race, arena).

# ---------------------------------------------------------------- daily sign-in / benefits

# CMsgSignIn 10253 (16 bytes). Mobile -> server: action u8 4 (CreateSignMsg 0 = sign today, CreateCumulatePrizeMsg
# 1 = claim the cumulative prize, index u32 8). Server -> mobile (Process): action 2 only, u32 8 = claimed prizes as a
# bitmask (bit n-1 = prize n, see CDlgSignIn: 1 << (i-1) & GetHadGetReward), u32 12 = signed days bitmask
# (COperateActivityData::IsSignInDay: bit d-1).
# Server (MsgSignIn.MsgSignInCreate): action u8 4 (3 = Show), claimed prize COUNT u8 5, u16 6, days mask u64 8;
# reader: action u8 4 (0 sign, 3 show), u32 5. The server's Show also hands out the cumulative prizes that are due, so
# the mobile "claim prize" (1) is sent as Show (3).
[2141 MsgSignIn struct 16 16]
4  4  u8  map 3>2 3<1       # action
5  8  u8  out map 1>1 2>3 3>7 4>15 5>31   # claimed prize count -> bitmask
5  8  u32 in                # prize index (unused by the server)
8  12 u32 out               # signed days

# CMsgBenefitsConfig 10131: count u32 4, then ST_BENEFITS_RULE {type, start yyyymmdd, end yyyymmdd} (12 bytes) from 8
# (CMsgBenefitsConfig::Process -> COperateActivityData::UpdateOperateBenefitsInfo(count, rules)).
# Server (MsgServerConfig.CreateBenefitsConfig): the same, but it writes count 4 with only 3 rules.
[2242 MsgBenefitsConfig struct 44 44]
4  4  u32 out map 4>3      # count
8  8  str:36 out           # 3 rules
